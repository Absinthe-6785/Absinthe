# K-30.34 — Planner Information Architecture Audit

**Context:** Planner exposes overlapping concepts: Day, Week, Month, Agenda, Weekly Timetable, Timeline, plus legacy Routines/Todos/Memo/D-Day columns. **Audit only — no feature removal in K-30.34.**

**Branch:** `k30-product-polish`

**Builds on:** `K-30.30-planner-consolidation-audit.md`, `K-30.32-planner-surface-reduction.md`

---

## Surface Map (current)

```
PlannerView
├── CalendarShell (PRIMARY)
│   ├── Month · Week · Day · Agenda  ← projection-backed
│   └── Period nav + mode switcher
├── Mobile tabs: todo | memo | calendar | timeline
├── Legacy Col-1: Routines + Todos
├── Legacy Col-2: D-Day + Memo (notes shortcut)
├── Legacy Col-3: Mini calendar (mobile only) + Timeline (48-slot grid)
├── WeeklyTimetableSection  ← sole weekly_schedules CRUD
└── Shared schedule / D-Day / exception modals
```

---

## 1. Surface Duplication

| Concept | Where it appears | Overlap |
| ------- | ---------------- | ------- |
| **Selected day** | CalendarShell anchor, legacy mini calendar, Timeline date, Todo/Routine date query | Same state (`selectedDate`) but **three visual hosts** |
| **Schedules** | Day view list, Timeline grid, Week/Month/Agenda event chips | Same API; dual CRUD entry (Day + Timeline) |
| **Todos / Routines** | Col-1 CRUD, Day/Week/Agenda read summaries | Execution only in Col-1 |
| **D-Day** | Col-2 panel, Month cells, Agenda countdown | CRUD only in Col-2 |
| **Weekly template** | Weekly Timetable section, Week/Day projection hints | CRUD only in Timetable |
| **Notes** | Memo column, event note clicks | Memo duplicates Notes tab |
| **Mark dots** | Legacy mini calendar (`markedDates`) | **Not** in CalendarShell projection |

**Duplication severity:** Medium-high on desktop (Timeline + Day list + Shell). Reduced on mobile via tabs but increases mode-switching cost.

## 2. Unique Surfaces (keep)

| Surface | Unique value |
| ------- | ------------ |
| **CalendarShell — Month** | 42-cell orientation, date pick |
| **CalendarShell — Week** | Multi-day column context |
| **CalendarShell — Day** | Schedule CRUD list + carry-over (K-30.31) |
| **CalendarShell — Agenda** | Horizon list + countdown section |
| **Timeline** | Time-proportional 48-slot grid, scroll-to-now |
| **Weekly Timetable** | Recurring template CRUD |
| **Routines / Todos Col-1** | Checkbox execution + exception modal |
| **D-Day panel** | Legacy countdown CRUD |

**Safe to demote (not delete):** Legacy mini calendar (desktop hidden K-30.32), Memo column (Notes tab canonical).

---

## 3. Weekly Timetable Integration Opportunities

| Integration | Status | Opportunity |
| ----------- | ------ | ----------- |
| Read hints in Week/Day | Done (projection `templateSlots`) | Show “edit template” deep link |
| CRUD in Shell | Not done | Add “Manage weekly template” entry in Week mode header |
| Agenda | Partial | Surface “recurring today” from templates |
| Day schedule create | Manual times | Prefill from template slot |

**Recommendation:** Treat Weekly Timetable as **“Recurring schedule template”** sub-mode of Week view (drawer or modal) rather than a disconnected section below the fold.

---

## 4. Day as Default Planner Entry

| Factor | Assessment |
| ------ | ---------- |
| `DEFAULT_PLANNER_CALENDAR_MODE` | Verify default is `day` (intent from K-30.30+) |
| User mental model | “What am I doing today?” → Day + Col-1 todos |
| Mobile | Default tab may still be `todo` not calendar — **misaligned** |
| Deep links | None land on Day mode explicitly |

**Recommendations:**
1. Default Shell mode = **Day** on all breakpoints.
2. Mobile default tab = **calendar** (Shell) not todo, or merge todo into Day view actions.
3. Persist last mode in `appSettings` (optional).

---

## 5. Mobile / Desktop Differences

| Capability | Desktop | Mobile |
| ---------- | ------- | ------ |
| CalendarShell | Always visible top | Always visible top |
| Legacy mini calendar | Hidden (`lg+`) | Calendar tab |
| Timeline | Always in Col-3 | Timeline tab |
| Routines/Todos | Col-1 always | Todo tab |
| Memo | Col-2 always | Memo tab |
| Weekly Timetable | Below fold | Below fold (long scroll) |

**Friction:** Mobile users must tab between **four** legacy surfaces plus Shell mode switch — high cognitive load.

**Recommendation:** Mobile IA → Shell-only primary (Day + Agenda) with floating action for todo/routine; demote Timeline to secondary menu.

---

## 6. Long-Term Planner Hierarchy

Proposed stable hierarchy (no removal, clear roles):

```
Planner
├── Today (Day)           ← default entry, schedule CRUD
├── Week                  ← multi-day + template hints
├── Month                 ← orientation
├── Agenda                ← horizon / countdown
├── Timeline (optional)   ← power-user time grid
└── Settings drawer
    ├── Weekly template CRUD
    ├── Routines & todos  (or link to Health)
    └── D-Day management
```

**Memo column:** Remove from default layout; rely on Notes tab + `openNote` from events (already wired K-30.33).
