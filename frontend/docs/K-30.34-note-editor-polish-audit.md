## 1. Reading Mode UX

**Strengths:** Wiki/tag click navigation; clean typography (`be-reading`); copy-friendly static spans.

**Gaps:**
- English mode hint (`Reading mode — double-click…`) vs Korean note content.
- Graph mode separate; no “print” or export-from-reading.
- Toggle chevron still interactive (correct) but empty toggles hidden only when no children.

**Follow-up:** Localize hint (Phase 1 language audit); optional fade hint after first visit.

---

## 2. Edit Mode UX

**Strengths:** Slash, wiki, gutter multi-select, undo via body history, Day-level stability fixes.

**Gaps:**
- Cross-block text selection stops at block boundaries.
- Tab → silent toggle nest (`ensureParentToggle`).
- Virtualization (POC) can break scroll-to-heading if enabled globally.

---

## 3. Slash Menu Discoverability

- Menu items Korean (`blockUtils.ts` catalog).
- `No results` English.
- No `/` hint in empty document beyond `EmptyDocumentHint` (edit only).
- Turn-into / context menu overlap increases choice paralysis.

**Recommendation:** Unified command palette stub or persistent “Insert block” on mobile.

---

## 4. Block-Type Visibility

- Turn-into and slash know types; reading mode hides chrome entirely.
- No “block type pill” on hover in edit (Notion-like).
- Divider/code/math visually distinct; paragraph vs heading relies on typography only.

---

## 5. Placeholder Density

| Mode | Before K-30.34 | After K-30.34 |
| ---- | -------------- | ------------- |
| Reading | Empty paragraphs showed `텍스트 입력…` | Hidden |
| Edit | Full Korean placeholder strings | Unchanged (correct) |

**Remaining:** Toggle header placeholder in edit; persistent paragraph placeholder when unfocused.

---

## 6. Outline Interaction Model

**Before:** Parent headings with children toggled collapse on row click — never scrolled.

**After K-30.34:**
- Row / title → `scrollToHeading` + active outline state + flash
- Chevron → collapse only
- Scroll scoped to editor pane via `editorScrollRef`

**Remaining:** TOC from markdown `#` lines only — toggle-nested headings in body may appear in TOC but lack `data-be-heading` if not root-level (edge case).

---

## 7. Folder Management UX

| Action | NoteView | PlannerView |
| ------ | -------- | ----------- |
| Create | Yes | Yes |
| Delete | Yes | Yes |
| Rename | **Yes (K-30.34)** | Yes (double-click) |
| Reorder | No | No |

**Recommendation:** F2 rename when folder focused; context menu parity with note list.

---

## 8. Note Search Discoverability

- Header search with document vs all-notes scope.
- Match index navigation easy to miss.
- No in-document highlight legend.

**Recommendation:** `/` focuses search when not in CE; show match count chip.

---

## 9. Toggle Usability

- K-30.33: append child instead of overwrite.
- `be-toggle-add-child` row in edit; hidden in reading.
- Empty toggle with children but empty title: chevron + children only (good).

**Gap:** Toggle Heading (H1–H4 Toggle block type) **not supported** — only paragraph-style toggle header.

---

## 10. Heading Hierarchy Support

| Feature | Status |
| ------- | ------ |
| H1–H3 blocks | Supported |
| H4 | **Not supported** (markdown `####` not parsed) |
| TOC | `#` `##` `###` lines only |
| Toggle as heading | No — toggle is separate type |
| Outline jump | Root headings only (`buildHeadingIndexById` depth 0) |
