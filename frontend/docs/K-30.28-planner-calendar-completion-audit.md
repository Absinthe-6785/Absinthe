## Current State

### Planner layout today

`PlannerView.tsx` renders **two parallel planning surfaces**:

1. **Calendar Shell** (top, always visible on all breakpoints) — projection-driven Month / Week / Day / Agenda switcher.
2. **Legacy three-column body** (below) — Routines + Todos | D-Day + Memo | legacy month picker + visual timeline.

Weekly Timetable sits **below** both (`WeeklyTimetableSection`).

```
PlannerView
├── CalendarShell          ← new read model (anchor = selectedDate)
├── Mobile tabs: todo | memo | calendar | timeline
├── Col-1: Routines + Todos (interactive CRUD)
├── Col-2: D-Day + Memo sidebar (interactive)
├── Col-3: Legacy month grid + 48-slot timeline (schedule CRUD)
└── WeeklyTimetableSection (interactive CRUD)
```

**Anchor date:** `CalendarShell` receives `anchorDate={formatDate(selectedDate)}`. Only the **legacy mini calendar** and daily data hooks change `selectedDate`. Calendar Shell has no prev/next chrome and month cells do not select dates.

### Day View — not a placeholder

Day View is a **full component tree** (`DayCalendarView`, `DayEventsSection`, `DayScheduleTimeline`, `DayTemplateHints`, `DayRoutineSummary`, `DayTodoSummary`) with **`dayView.test.tsx`** (15+ scenarios).

Important distinction vs legacy timeline:

| Capability | Legacy timeline (Col-3) | Day View (Calendar Shell) |
| ---------- | ------------------------ | ------------------------- |
| Visual 30-min grid | Yes (48 slots) | No — flat schedule list |
| Schedule create/edit/delete | Yes (modal + inline) | No |
| Carry-over `end_next_day` | Yes (positioned) | Yes (list only) |
| Note events | No | Yes (clickable) |
| Weekly template hints | No | Yes (read-only) |
| Routines / todos | Interactive in Col-1 | Read-only summary in Day View |

Day View is **implemented for scanning a day from the projection**; it does **not** replace the legacy execution column.

## Missing Components

### Calendar UI gaps

1. **Agenda View UI** — only placeholder; projection + presentation labels exist (`agendaHorizonLabel`, `agendaDateHeaders`).
2. **Calendar Shell date navigation** — no prev / next / today; cannot browse without legacy mini calendar.
3. **Month / Week date selection in Shell** — cells/columns highlight anchor but clicks do not update `selectedDate` (except via legacy picker).
4. **Day View execution wiring** — no hooks to existing routine/todo/schedule mutators; timeline is not interactive.
5. **Unified period chrome** — Month/Week/Day headers duplicate label patterns; no shared nav bar (addressed in K-30.28 step 1).

### Consolidation gaps (not calendar-mode gaps)

6. **Legacy Col-3 retirement path** — timeline + mini calendar still own schedule CRUD.
7. **Memo column** — duplicates Note tab (`useNotesStore` in Planner); K-30.17 recommends removal.
8. **D-Day dual surface** — CRUD panel + `legacyDdays` in projection; convergence deferred.
9. **Mobile tab model** — tabs reference legacy `calendar` / `timeline` columns, not Calendar Shell modes; Shell sits above tabs on mobile (always visible), causing vertical stacking duplication.

**Obsolete UI (candidates for phased hide after Shell nav):**

**Keep during transition:**

## Recommended Implementation Order

### Milestone recommendation (next after Month + Week)

**K-30.29 — Agenda View UI**

Agenda is the **only Calendar Shell mode still on `CalendarViewPlaceholder`**, while `buildAgendaViewPayload` and presentation labels are fully tested. Shipping Agenda completes the four-mode shell before consolidation retires legacy columns.

Agenda UI should:

- Render `projection.views.agenda.countdownSection` + `dayGroups`
- Reuse presentation `agendaDateHeaders` / `agendaHorizonLabel`
- Support `onEventNoteClick` for note-backed items
- Stay read-only initially (match Month/Week/Day pattern)

### Prerequisite micro-milestone (low risk, enables consolidation)

**K-30.28 — Calendar Shell date navigation** *(implementation started on this branch)*

1. Add period prev / next / today chrome to `CalendarShell` (`shiftPlannerAnchorDate` by mode).
2. Wire `onAnchorDateChange` → `PlannerView` `setSelectedDate` + `setCurrentDate`.
3. Optional follow-up: month cell / week column click → set anchor.

This does not remove legacy UI yet; it makes Calendar Shell **self-sufficient for date browsing**.

### Subsequent milestones

| Order | Milestone | Purpose |
| ----- | --------- | ------- |
| 3 | **Day View execution parity** | Pass schedule/routine/todo handlers; optional visual timeline port into Day mode |
| 4 | **Hide legacy mini calendar** | After Shell nav + cell select verified |
| 5 | **Planner column collapse** | Single Shell + side execution drawer; retire Memo column on separate track |
| 6 | **D-Day convergence** | Architecture only when Event model work is scheduled — out of scope here |

## Risks

| Risk | Severity | Mitigation |
| ---- | -------- | ---------- |
| Retiring legacy timeline before Day CRUD | **High** | Do not hide Col-3 until Day View wires `openModal` / schedule handlers |
| Removing Memo column | **Medium** | Users may rely on Planner-side note list; communicate Note tab + optional quick-open |
| Dual calendar confusion | **Medium** | Ship Shell nav first; then hide legacy picker in one PR with release note |
| Agenda 14-day horizon performance | **Low** | Projection already indexes range; UI is list render |
| Read-only Day routines frustrate users | **Medium** | Label Day View as summary until step 3; keep Col-1 visible |
| `selectedDate` vs `currentDate` drift | **Low** | Centralize anchor changes through one callback (K-30.28) |
| Mobile vertical scroll bloat | **Medium** | Defer layout consolidation until legacy columns phased |
