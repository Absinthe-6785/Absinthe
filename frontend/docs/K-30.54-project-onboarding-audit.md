# K-30.54 — Project Onboarding Audit

**Branch:** `k30-discoverability-i18n`

---

## Before

Users needed to know:

- `studyProject=yes` property
- `studyProjectStatus` values
- `studyProjectId` for linking milestones

Empty state mentioned `studyProject` jargon.

## After

### Create Project Dialog

| Field | Maps to |
| ----- | ------- |
| Project name | note title |
| Description | `studyProjectDescription` |
| Subject (optional) | subject tag via `addTag` |
| Status | `studyProjectStatus` |

Auto-sets `studyProject=yes` via `setStudyProjectContainer`.

### Create Milestone Dialog

| Field | Maps to |
| ----- | ------- |
| Milestone name | note title |
| Target date | `milestoneTargetDate` |
| Project picker | `studyProjectId` |
| Status | `milestoneStatus` |

Auto-sets `projectMilestone=yes` via `setProjectMilestone`.

### Entry Points

- Project quick actions → dialog
- Project dashboard empty state → Create Project
- Milestone quick action → dialog (requires project)

## Remaining

- Link existing notes to project from dialog
- Template projects (EJU, TOEFL presets)
- Milestone quick action when zero projects → redirect to create project

## Success Criteria

No manual property editing required for standard project/milestone creation.
