# K-30.32 — Planner Surface Reduction

**Context:** Post–K-30.31. Calendar Shell is the primary planning surface (Month · Week · Day · Agenda). Day View supports schedule add/edit/delete via the same modal and confirm flows as Timeline. Legacy Planner columns remain below the shell.

**Branch:** `k30-planner-polish` lineage.

**Method:** Source inspection of `PlannerView.tsx`, `CalendarShell.tsx`, `WeeklyTimetableSection.tsx`, and projection layer — updated from K-30.30 after Day View execution wiring.

---

## Current Planner Surface Inventory

| Surface | Location | Visibility | Primary data | Interaction |
| ------- | -------- | ---------- | ------------ | ----------- |
| **CalendarShell** | Top of Planner (always) | All breakpoints | Projection (notes + daily props) | Mode switch, period nav, date pick (Month), event note click, Day schedule CRUD |
| **Mobile tab bar** | Below shell | `lg:hidden` | Tab state only | `todo` · `memo` · `calendar` · `timeline` |
| **Col-1 Routines** | Legacy body | Mobile: todo tab; Desktop: always | `GET /api/routines_with_logs` | Toggle, edit, delete, exception modal |
| **Col-1 Todos** | Legacy body | Same as routines | `GET /api/todos?date=` | Add, toggle, edit, delete |
| **Col-2 D-Day panel** | Legacy body | Mobile: memo tab shares col; Desktop: always | `GET /api/schedules/ddays` | Legacy D-Day CRUD modal |
| **Col-2 Memo** | Legacy body | Mobile: memo tab; Desktop: always | `useNotesStore` | Folder sidebar, inline editor, trash |
| **Col-3 Legacy mini calendar** | Legacy body | Mobile: calendar tab; Desktop: **hidden (K-30.32)** | `buildCalendarDays` + `markedDates` | Month prev/next, day select, mark dots |
| **Col-3 Timeline** | Legacy body | Mobile: timeline tab; Desktop: always | `GET /api/schedules?date=` + carry-over | 48-slot grid, schedule CRUD modal |
| **Weekly Timetable** | Below columns | Always | `GET /api/weekly_schedules` | Recurring template CRUD modal |
| **Modals** | Overlay | On demand | Shared handlers | Schedule, D-Day, routine exception, confirm |

### Render tree (post K-30.32)

```
PlannerView
├── CalendarShell                         ← primary (orientation + Day CRUD)
├── Mobile tabs: todo | memo | calendar | timeline
├── Col-1: Routines + Todos               ← daily execution CRUD
├── Col-2: D-Day + Memo                   ← legacy CRUD + Note shortcut
├── Col-3: Legacy mini calendar (mobile)  ← transitional; hidden lg+
│          + Timeline (all lg+, mobile timeline tab)
├── WeeklyTimetableSection                ← unique weekly template CRUD
└── Modals
```

## Responsibilities Already Covered By CalendarShell

| Responsibility | Shell mode(s) | Notes |
| -------------- | ------------- | ----- |
| Month grid browsing | Month | 42-cell projection grid; cell click → `onAnchorDateChange` |
| Month / week / day / agenda period labels | All + `CalendarPeriodNav` | Prev / next / Today sync `selectedDate` |
| Anchor date sync | All modes | `handleCalendarAnchorChange` updates `selectedDate` + `currentDate` |
| Note-backed events (read) | Month, Week, Day, Agenda | `onEventNoteClick` → Memo `activeNoteId` |
| Day schedule list (read) | Day | Flat blocks + carry-over display |
| Day schedule CRUD | Day | `dayScheduleActions` → `openModal` / `handleDeleteSchedule` (K-30.31) |
| Weekly template hints (read) | Week, Day | Projection `templateSlots` — no CRUD |
| Legacy D-Day countdowns (read) | Month cells, Agenda | Projection `legacyDdays` — no CRUD |
| Routines / todos (read summaries) | Day, Week, Agenda | Projection bundles — no checkbox CRUD |
| Today / milestone indicators | Day header | Presentation labels |

**Not covered by Shell (intentionally):** routine/todo checkbox CRUD, weekly template CRUD, legacy D-Day CRUD, Memo editor, Timeline 48-slot visual layout, **`markedDates` domain dots**.

## Remaining Unique Responsibilities

| Surface | Unique capability | Why Shell cannot replace it yet |
| ------- | ----------------- | ------------------------------- |
| **Timeline** | 48-slot visual grid, time-proportional blocks, auto-scroll to now, carry-over layout | Day View has list CRUD but not grid visualization; secondary path by design |
| **Routines (Col-1)** | Done toggle, text edit, delete, **exception day modal** | Day View shows read-only routine summary |
| **Todos (Col-1)** | Add / toggle / edit / delete for selected day | Day View shows read-only todo summary |
| **Weekly Timetable** | Sole `weekly_schedules` CRUD | Shell only mirrors templates in Week/Day hints |
| **D-Day panel** | Sole legacy D-Day API CRUD | Shell shows countdowns read-only in Month/Agenda |
| **Memo** | Planner-local folder sidebar + inline editor | Note tab is canonical; Memo is convenience duplicate |
| **Legacy mini calendar (mobile)** | **`markedDates` dots** from `/api/schedules/dates` | Marks not in projection; mobile-only after K-30.32 |
| **Schedule modal** | Overlap confirm, `end_next_day`, color/category | Shared by Timeline + Day View — keep |

## Safe Removal Candidates

“Removal” in this phase means **hide or demote**, not delete code paths.

| Candidate | Action | Capability preserved via | Risk |
| --------- | ------ | -------------------------- | ---- |
| **Legacy mini calendar (desktop)** | Hide `lg+` | CalendarShell Month + period nav + Day mode | Low — **implemented K-30.32** |
| **Mobile `calendar` tab** | Retire tab (K-30.33) | CalendarShell always above tabs | Medium — mobile loses mark dots unless migrated |
| **Memo column** | Collapse / link to Note tab (K-30.35) | Note tab + `onEventNoteClick` | Medium — muscle memory |
| **D-Day panel (CRUD)** | Read-only strip then Note events (K-30.36+) | Agenda countdowns + Event architecture | High — needs Event CRUD |
| **Timeline (display)** | Hide when Day grid parity (K-30.37+) | Day View + modal | High — grid UX gap today |
| **Col-1 split layout** | Merge into “Today execution” panel (K-30.34) | Same handlers, smaller footprint | Medium |

**Do not remove in this track:** Timeline schedule CRUD handlers, Weekly Timetable, routine/todo CRUD, schedule modal, Archive, Note architecture, Event model.

## Migration Risks

| Risk | Severity | Mitigation |
| ---- | -------- | ---------- |
| Losing `markedDates` on desktop | **Medium** | Marks only on legacy picker; desktop users rely on Shell until marks join Month projection |
| Mobile duplicate calendar (shell + tab) | **Low–Med** | K-30.33 tab simplification; shell already visible on mobile |
| Timeline hidden before Day grid parity | **High** | Do not hide Timeline CRUD; K-30.31 list CRUD is not grid replacement |
| Memo removal breaks workflows | **Medium** | Deprecation banner before removal; Note tab parity |
| D-Day CRUD gap during Event convergence | **High** | Keep panel until Note event UX documented (K-30.21) |
| `currentDate` / `selectedDate` drift | **Low** | Single `handleCalendarAnchorChange` (K-30.28+) |
| Monolithic `PlannerView` refactor | **Low** | Extract after surface plan stable |

## K-30.32 Implementation

**Change:** Legacy mini calendar card uses `lg:hidden` — visible only on mobile when the **Calendar** tab is active. Timeline remains on desktop (`lg:flex`).

**Rationale:** CalendarShell already provides month browsing, period navigation, and Day drill-down on desktop. Hiding the duplicate picker reduces visual clutter without deleting handlers or mobile mark-dot access.
