# K-30.36 — Planner Mobile Audit

**Branch:** `k30-editor-consistency`  
**Scope:** Task D — align mobile entry with Day-first desktop (K-30.35)

---

## Previous Behavior

| Aspect | Desktop | Mobile |
| ------ | ------- | ------ |
| CalendarShell default | Day (K-30.35) | Day (same component, always visible) |
| Legacy tab default | N/A | **`todo`** — routines/todos column |
| Tab order | N/A | todo · memo · calendar · timeline |
| User lands on | Day schedule list | Todo list first — misaligned with Day-first IA |

Mobile users saw CalendarShell at top but the **active legacy tab** emphasized todo execution, not calendar/day workflow.

---

## Updated Behavior (K-30.36)

| Change | Detail |
| ------ | ------ |
| Default mobile tab | **`calendar`** (legacy mini calendar + same tab hosts timeline sibling visibility rules unchanged) |
| Tab order | **calendar · todo · memo · timeline** — calendar first in tab bar |
| Preserved | Routines/todos CRUD, memo, timeline, Weekly Timetable, all CalendarShell modes |

---

## Remaining Inconsistencies

| Item | Notes | Priority |
| ---- | ----- | -------- |
| Dual calendar surfaces | Shell Day view + mobile mini calendar tab | P2 — demote mini calendar per K-30.32 |
| Tab vs Shell | Shell always visible; tabs only show/hide legacy columns | P3 — long-term merge into Shell-only mobile |
| English legacy headers | Timeline, D-Day panel copy | P2 — language pass |
| Todo-first mental model | Users with todo-heavy workflow must tap todo tab | Acceptable tradeoff for Day-first product direction |

---

## Success Criteria

Opening Planner on mobile defaults to the **calendar** tab, matching desktop Day-first entry via CalendarShell.
