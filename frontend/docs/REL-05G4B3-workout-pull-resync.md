# REL-05G4B3 — dormant Workout pull and fixed-watermark full resync

This slice consumes the existing G4A Workout transport; it does not change backend SQL, activate Health UI, start a worker, or acknowledge push from pull. The only entry points are explicit `runWorkoutPullIteration` and `runWorkoutFullResync` calls. They never use legacy `/api/workouts` as fallback. G4C reset, G5 cutover, and G6 ACTIVE remain deferred.

## Account-wide incremental pull

The authenticated request uses the locally bound namespace/generation/device/binding for authorization, but the G4A SQL selects Workout changes by authenticated owner, project scope and domain, **not producer namespace/generation**. The dedicated `workout_g4a` checkpoint starts at cursor 0 and stores `serverEpoch` and the highest consumed stream sequence. A missing/invalid cursor or epoch mismatch requests resync without deleting local state. A validated empty page keeps the same cursor. Malformed pages never enter the canonical transaction.

The page validator checks protocol, domain, authority epoch, server epoch, retention floor, cursor, ordered sequences, operation/deletion coherence, UUIDs, timestamps, canonical WorkoutSessionV1 shape, and exact canonical content hash. Multiple events for the same entity are applied in sequence in one transaction; their server revisions must increase. No event is collapsed before that check. A newer clean remote revision creates a new *local* revision and stores remote revision/state/ref/hash independently, so the next local mutation receives the existing remote sequence boundary. A tombstone retains the server's canonical Workout record. No pull apply creates an outbox row.

The IndexedDB transaction checks the active generation, synchronous account/device identity, bound authority and unexpired lease token/epoch. UUID sidecar mapping, canonical entity changes, deterministic conflict evidence and checkpoint are written together. A case-only local UUID collision fails closed. The original local key spelling is retained; Workout repository read/update/delete/restore checks compare UUID *values* and resolve a wire-form ID through the sidecar, so a server record with different letter case remains usable without rewriting its payload or hash. A direct case-only twin alongside the mapping fails closed. For a pending local lineage, the remote candidate is preserved as a conflict and local content/outbox is untouched; the checkpoint may advance because the candidate is durable. An acknowledged receipt with the same remote ref/revision/commit evidence is an own echo and does not conflict with a newer local M2. An unacknowledged response-lost M1 never becomes acknowledged from pull; its exact G4B2 replay path remains intact. Older revisions cannot regress canonical state, and divergent same-revision evidence fails closed.

## Fixed-watermark snapshot

G4A issues `snapshotToken`, `serverEpoch` and immutable `watermark`. Pages are ordered by `entityId`, each row is the latest change at or before that watermark, and concurrent W+1 writes are intentionally excluded. The explicit driver downloads at most one page per call into the v7 `workout_full_resync_sessions` and `workout_full_resync_items` stores. Session identity, binding, epoch, watermark, progress, phase and item count are durable. A crash during staging resumes from the stored `afterEntityId`. A crash after the final page leaves a `ready` session; the next call commits it. Token invalidation abandons only the staging session, never canonical records.

The canonical commit is one bounded IndexedDB transaction (maximum 10,000 staged rows and 8 MiB of canonical row data). Overflow fails closed with staging intact; it never falls back to a partial multi-transaction apply. The staged byte count is checked again before commit. Snapshot rows, UUID mappings, canonical records, conflicts, exact watermark checkpoint/serverEpoch and committed phase are atomic. The store is never cleared. Local-only or pending first creates absent from the snapshot remain intact. A previously remote-established record absent from a complete snapshot is also preserved, with deterministic conflict evidence that blocks a later unsupported CAS inference; omission is not treated as deletion. Pending local content always wins preservation, with the remote snapshot candidate retained as conflict. After commit, incremental pull resumes from watermark W, receiving W+1 normally.

## Operational boundaries

The same durable `workout_pull_g4b3` lease serializes page and snapshot commits across tabs. Network requests occur outside IndexedDB transactions; an expired/reclaimed lease cannot commit. Auth account, durable device, active generation and authority binding are rechecked before durable mutation. Diagnostics contain only event names/codes, never access tokens or Workout payloads. The v7 database version remains unchanged. This is a dormant foundation, not user-visible sync or a repair flow for legacy Workout data.
