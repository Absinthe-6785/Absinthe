# K-30.30 — Planner Consolidation Audit

**Context:** Post–K-30.29. All Calendar Shell modes (Month · Week · Day · Agenda) are implemented. Calendar period navigation (`CalendarPeriodNav`) is wired to `selectedDate`. Legacy Planner columns remain below the shell.

**Branch audited:** Workspace state on `k30-calendar-next` lineage (PlannerView + `calendar-ui/*`).

**Method:** Source inspection of `PlannerView.tsx`, `WeeklyTimetableSection.tsx`, `CalendarShell.tsx`, and projection layer — not milestone labels alone.

---

## Current Planner Architecture

### Render tree (actual)

```
PlannerView (~950 lines, monolithic)
├── CalendarShell                    ← primary read surface (always visible)
│   ├── CalendarModeSwitcher         ← Month / Week / Day / Agenda
│   ├── CalendarPeriodNav            ← prev / next / Today → selectedDate
│   └── Mode view (projection-driven)
├── Mobile tab bar                   ← todo | memo | calendar | timeline
├── Col-1 (lg flex-[2])              ← Routines + Todos (CRUD)
├── Col-2 (lg flex-[2.2])            ← D-Day panel + Memo sidebar (CRUD)
├── Col-3 (lg flex-[3.5])            ← Legacy mini calendar + Timeline (schedule CRUD)
├── WeeklyTimetableSection           ← weekly template CRUD
└── Modals                           ← schedule, D-Day, routine exception, confirm
```

### Data flow

| Surface | Primary data | Anchor |
| ------- | ------------ | ------ |
| CalendarShell | `usePlannerCalendarProjection` (notes + daily props) | `formatDate(selectedDate)` |
| Routines / Todos | `GET /api/routines_with_logs`, `GET /api/todos` | `selectedDate` |
| Timeline | `GET /api/schedules?date=` + carry-over from prev day | `selectedDate` |
| D-Day panel | `GET /api/schedules/ddays` via `legacyDdays` | global list |
| Memo | `useNotesStore` | folder filter (not date-scoped) |
| Weekly Timetable | `GET /api/weekly_schedules` | weekday template (not anchor) |
| Legacy mini calendar | `buildCalendarDays(currentDate)` + `markedDates` | `currentDate` / `selectedDate` |

**Anchor sync:** `handleCalendarAnchorChange` updates both `selectedDate` and `currentDate` (month start). Legacy mini calendar month nav uses `setCurrentDate` independently.

## Duplicate Surfaces

| Duplicate | Shell / new | Legacy / old | What overlaps | What legacy still uniquely provides |
| --------- | ----------- | ------------ | ------------- | ----------------------------------- |
| **Month date browsing** | `MonthCalendarView` + `CalendarPeriodNav` | Col-3 mini calendar | Month grid, prev/next month, day selection | **`markedDates` dots** (domain marks from `/api/schedules/dates`) — not in projection |
| **Day schedule display** | `DayCalendarView` → flat block list | Col-3 Timeline | Same-day `schedules` blocks, carry-over | **Visual 48-slot grid**, inline edit/delete, `openModal()` CRUD |
| **D-Day countdowns** | Month cells, Agenda countdowns, projection `legacyDdays` | Col-2 D-Day panel | Same `ddays` API in projection | **CRUD** (add/edit/delete legacy D-Day rows) |
| **Weekly template** | Week `templateSlots`, Day `DayTemplateHints` | `WeeklyTimetableSection` | Read mirror of `weeklySchedules` | **Only CRUD** for recurring blocks |
| **Note access** | Shell `onEventNoteClick` → memo `activeNoteId` | Memo column + Note tab | Same `useNotesStore` | Folder sidebar + inline editor in Planner |
| **Routines / todos (read)** | Day / Week / Agenda summaries | Col-1 panels | Same-day data in projection | **Checkbox CRUD**, exception modal, add/delete |
| **Mobile “Calendar” tab** | CalendarShell already above tabs | Col-3 mini calendar when tab active | Second month picker on mobile | Mark dots only on legacy picker |

### Transitional surfaces (keep until migration completes)

1. **Col-3 Timeline** — sole schedule execution UI until Day View wires `openModal` / delete handlers.
2. **Col-3 mini calendar** — sole **`markedDates`** indicator until marks join projection or Archive-style domain layer.
3. **Col-2 D-Day panel** — sole legacy D-Day CRUD until Event convergence (K-30.21 architecture; no model change in this phase).
4. **Col-2 Memo** — convenience shortcut; duplicates Note tab per K-30.17.
5. **Mobile tab model** — predates CalendarShell; references legacy columns not shell modes.

### Surfaces that should become secondary

| Surface | Role after consolidation |
| ------- | ------------------------ |
| Legacy mini calendar | Hidden on desktop first; mobile-only until marks migrate |
| Memo column | Collapsed drawer or removed → Note tab + event click |
| D-Day panel | Read-only countdown strip in Agenda/Month until Event CRUD exists in Note |
| Col-1 on desktop | Side execution panel; Day mode could host routine/todo actions later |
| Weekly Timetable | Stays as **supporting tool** below calendar (not inside shell modes) |

## Unique Functional Surfaces

These have **no full replacement** in CalendarShell today:

| Surface | Unique capability | Must keep until |
| ------- | ----------------- | --------------- |
| **Timeline (Col-3)** | Schedule create/edit/delete, overlap confirm, `end_next_day` visual layout | Day View execution parity (K-30.31) |
| **Routines (Col-1)** | Toggle done, edit text, delete, **exception day modal** | Routine actions wired to Day View or fixed side panel |
| **Todos (Col-1)** | Add / edit / delete / checkbox | Same |
| **Weekly Timetable** | `weekly_schedules` CRUD modal | Never duplicated in shell — permanent supporting section |
| **D-Day panel** | Legacy D-Day API CRUD | Event-backed countdown CRUD in Note |
| **Memo** | Planner-local note list + editor | Optional — Note tab is canonical |
| **Legacy mini calendar** | `markedDates` domain dots | Marks in projection or dropped intentionally |
| **Schedule modal** | Shared by timeline | Reused by future Day View actions |

## Recommended Future Architecture

Target hierarchy (calendar-centered, execution adjacent):

```
Planner
├── CalendarShell (primary — orientation + drill-down)
│   ├── Month / Week / Day / Agenda
│   └── Period nav + anchor sync
├── Execution row (desktop: single row or collapsible)
│   ├── Routines + Todos        ← daily checklist (CRUD)
│   └── Schedule actions        ← modal entry from Day mode or compact strip
├── Weekly Timetable            ← recurring template (unchanged ownership)
└── Supporting tools (secondary)
    ├── D-Day legacy CRUD       ← shrink → Agenda countdowns + Note events
    └── Memo                    ← deprecate → Note tab
```

### Design decisions (recommended)

| Question | Recommendation |
| -------- | -------------- |
| Remove Memo? | **Yes, phased** — after verifying users rely on Note tab; keep Memo one release with deprecation banner |
| D-Day → Events? | **Yes, long-term** — projection already dedupes; panel becomes read-only then removed |
| Timeline vs Day View? | **Evolve** — Day View becomes execution surface; timeline grid ported or embedded in Day mode; do not delete timeline until parity |
| CalendarShell as landing? | **Yes** — already first in DOM; collapse legacy Col-3 on `lg+` once Day CRUD + marks path clear |
| Weekly Timetable position? | **Below shell** — not a calendar mode; optional collapse |

## Risks

| Risk | Severity | Mitigation |
| ---- | -------- | ---------- |
| Removing timeline before Day CRUD | **Critical** | Phase 1 gate for Phase 7 |
| Losing `markedDates` when hiding legacy picker | **Medium** | Phase 2 only on desktop; add marks to month projection in parallel |
| Memo removal breaks Planner muscle memory | **Medium** | Deprecation banner; measure usage |
| D-Day CRUD gap during convergence | **Medium** | Keep panel until Note event UX documented |
| Mobile scroll bloat (shell + tabs + columns) | **Medium** | Phase 3 tab simplification |
| `currentDate` / `selectedDate` drift | **Low** | Single `handleCalendarAnchorChange` (done) |
| Splitting monolithic `PlannerView` | **Low** | Extract after consolidation plan stable |

## Recommended Implementation Order

1. **K-30.30** — This audit; **month cell date pick** in Shell (enables legacy picker retirement).
2. **K-30.31** — Day View execution: pass `onAddSchedule`, `onEditSchedule`, `onDeleteSchedule` from PlannerView; optional visual timeline component reuse.
3. **K-30.32** — Hide legacy mini calendar on desktop (`lg+`); document `markedDates` follow-up.
4. **K-30.33** — Simplify mobile tabs to `today | memo | timeline` or `today | timeline` (shell always visible).
5. **K-30.34** — Unified “Today” execution column (routines + todos); reduce Col-1 footprint.
6. **K-30.35** — Memo deprecation path.
7. **K-30.36+** — D-Day / Event convergence (architecture track, separate milestone).
