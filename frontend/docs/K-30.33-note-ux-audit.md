## Current Editor Interaction Model

### Modes

| Mode | `readOnly` | Block surface | Active block |
| ---- | ---------- | ------------- | ------------ |
| **Edit** | `false` | One `contentEditable` per focused text block; others render `.be-editable-static` | `activeBlockId` in `BlockEditorInner` |
| **Reading** | `true` | All blocks static (`be-editable-static` or read spans) | No CE focus |
| **Graph** | N/A | Separate `NoteGraphView` | — |

Toggle: **Ctrl+E** cycles edit ↔ reading (skips graph). Reading mode enables wiki link follow on click.

### Block operations (edit mode)

| Interaction | Mechanism |
| ----------- | --------- |
| Typing / Enter / merge | `EditableBlock` + `useEditorBlockEditing` |
| Slash / wiki menus | `useEditorMenus` |
| Gutter multi-select | Shift+click, Shift+drag on gutter (`useEditorGutterDrag`) |
| Block delete (selected) | Capture-phase keyboard (`blockKeyboard.ts` + `useEditorKeyboard`) |
| Drag reorder | Grip pointer (`useEditorGutterDrag` / `editorDragDrop`) |
| Tab nest | `indentBlock` → `ensureParentToggle` + `moveBlockIntoToggle` |
| Toggle children | Recursive `BlockEditorInner`; header Enter via `applyToggleHeaderEnter` |
| Document chrome click | `useEditorDocumentFocus` → `focusNearestEditable` / toggle footer insertion |
| Virtualization | Optional `VirtualBlockList` — off-screen blocks unmounted |

### Navigation to notes

| Surface | Handler | Switches to Notes tab? |
| ------- | ------- | ---------------------- |
| Note list, backlinks, graph, DB views, trace lists | `setActiveNoteId` | Already on Notes tab |
| Areas sidebar (primary click) | `openCreatedNote` | Yes |
| Areas sidebar (Ctrl/Meta/Alt) | `openTraceArea` | Yes (trace lens) |
| Planner calendar events | `onEventNoteClick` → `setActiveNoteId` | **No** — stays on Planner |
| Planner memo sidebar | `setActiveNoteId` | **No** |
| Archive milestones / area pills | `setActiveNoteId` | **No** — stays on Analytics (Archive) |
| Archive Mark Calendar day click | **Not wired** | — |
| Archive Browse links | **Not wired** (`onBrowseClick` optional, unused) | — |

Tab state lives in `AppContent` (`activeTab`); `useNotesStore.setActiveNoteId` is global but does not change tabs.

## Friction Points

| Area | Symptom | Root cause |
| ---- | ------- | ---------- |
| **Cross-block text selection (edit)** | Drag selection stops at block boundaries | Single active CE architecture; activating a block swaps static → CE and collapses range |
| **Cross-block activation** | Accidental focus while selecting (partially mitigated) | `EditableBlock` mouseup defers activation if drag > 4px or selection non-collapsed; padding/chrome still aggressive in places |
| **Toggle empty rows** | Identical `▶ Toggle` placeholders at every depth | CSS placeholder on empty header; no disambiguation |
| **Toggle add child (non-empty)** | No obvious control after first child | Empty-state `내용 추가…` only when `children.length === 0`; footer click zone exists but undiscoverable |
| **`handleToggleAddChild` overwrite** | Would destroy existing children if called with non-empty toggle | Set `children: [newChild]` instead of append (fixed K-30.33) |
| **Tab indent surprise** | Previous sibling silently becomes toggle | `ensureParentToggle` side effect without confirmation |
| **Archive / Planner note open** | Note ID updates but user sees wrong tab | No cross-tab navigation API |
| **Mark Calendar / Browse** | Clicks are no-ops on Archive Home | Handlers not passed from `ArchiveHomeView` |
| **Mobile Notes** | Two-step list → editor | `mobileShowEditor` gate; expected but adds taps |
| **Virtualization** | Long selections skip off-screen blocks | Unmounted DOM rows |

## Toggle UX Evaluation

### Current authoring flows

| Flow | How | Issues |
| ---- | --- | ------ |
| Create toggle | Slash `toggle` · Turn into · Ctrl+Shift+8 | OK |
| First child | Empty toggle `내용 추가…` · header Enter at end · footer click zone | OK once discovered |
| More children | Enter in last child · footer zone click below children | Footer zone undiscoverable |
| Nest under toggle | Tab on block below sibling | Converts previous block to toggle — surprising |
| Nested toggle inside toggle | Tab when prev sibling is toggle-capable | Works; empty titles look identical |
| Collapse / expand | Chevron on header | OK |
| Add child button | **K-30.33:** `be-toggle-add-child` when expanded + has children | Improves discoverability |

### Should the editor support this structure directly?

```
Toggle
├── Toggle 1
├── Toggle 2
└── Toggle 3
```

**Recommendation:** **Yes, but incrementally** — no schema change needed (`children[]` already supports it).

| Approach | Effort | Risk |
| -------- | ------ | ---- |
| Tab nest (current) | Done | Surprise conversion |
| Footer / add-child affordance | Low | Low — **shipped K-30.33** |
| Slash “Toggle group” template (3 empty child toggles) | Medium | Low |
| Turn-into “Toggle with children” | Medium | Medium |
| Auto-title placeholders (`Toggle 1`, …) | Low–Med | Content pollution if written to `content` — prefer UI labels |

**Do not** change Tab semantics until append paths and discoverability are stable.

## Selection UX Evaluation

### View (reading) mode

- All blocks static → native cross-block drag selection works.
- Wiki links: Ctrl/Meta+click navigates.

### Edit mode

**Architecture (fundamental):**

```
Reading:  [static][static][static]…  → full DOM selection
Edit:     [static][ CE  ][static]…  → selection cannot span CE ↔ static
```

**Contributing behaviors:**

1. **`EditableBlock` static path** — mouseup activation deferred when drag > 4px or `window.getSelection()` non-collapsed (already implemented).
2. **`handleContentMouseDown`** (`SingleBlock`) — `preventDefault()` on non-text chrome (padding, toggle row shell) blocks drag-start from those regions.
3. **Gutter drag** — clears text selection on start (`removeAllRanges`) — intentional for block selection.
4. **Virtualization** — breaks selections spanning unmounted rows.

### Cross-block text selection — deep dive (Task A)

| Question | Answer |
| -------- | ------ |
| **Root cause** | By design: one active CE per edit session + static siblings for performance. Not a regression. |
| **Complexity to “fix” fully** | **High** — requires multi-CE overlay, selection-aware activation FSM, or reading-mode-first copy UX |
| **Recommended solution** | **Tiered:** (1) Keep reading mode as canonical for copy — add discoverability hint; (2) defer activation improvements already in `EditableBlock`; (3) optional “selection mode” flag later; (4) do **not** duplicate CE per block without performance review |

## Navigation UX Evaluation

### Should these switch to the Notes tab?

| Interaction | Should open Notes tab? | Rationale |
| ----------- | ---------------------- | --------- |
| Archive milestone click | **Yes** | User expects to read/edit the milestone note |
| Archive area pill click | **Yes** | Opens area hub note |
| Archive Browse (period/timeline) | **No** — switch Archive mode first | Wayfinding within Archive, not Note editor (when views exist) |
| Mark Calendar day click | **Maybe** — trace/day lens or Note | Product choice: day trace in Notes vs Archive period view |
| Planner event click | **Yes** | Event-backed notes are primary content |
| Planner memo note click | **Yes** (optional) | Already in Planner context; tab switch optional |
| Wiki link in editor | **Yes** (same tab) | Already navigates within NoteView |

**Implementation gap:** `AppContent.activeTab` is local state. Needs a small **navigation intent** channel (e.g. `useNotesStore.openNote(id, { focusTab: 'note' })` + `AppContent` subscriber) — **not** a note schema change.

**Priority:** High user impact, medium effort, isolated to App shell + call sites.
