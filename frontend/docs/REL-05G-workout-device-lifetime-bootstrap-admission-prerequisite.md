## 2. Exact original Slice 2 blocker

[The foundation](../src/lib/workoutDeviceLifetimeAuthority.ts), lines 60-65 and 240-243, accepts a caller-supplied `DeviceAuthorityAdmission` with `compatibleCreatorsQuiesced: true` and a creator/legacy-reader role. `assertAdmission` validates the supplied claim; it does not discover contexts or prove that claim. The production factory (371-378) supplies browser ports only. No production caller currently imports the foundation. Tests supplying the flag are not rollout evidence.

Production cannot currently assert that flag truthfully: the raw helper is still used by independent sync, control-plane and creation-capable reader paths, and there is no production owner of verified compatible-context admission. Even after every NEW-build path is routed, current metadata cannot prove that an OLD already-loaded context capable of bypassing the protocol has exited. Supplying a constant would hide both missing work and an information-theoretic limit.

| Distinct proposition | What proves it; what does not |
| --- | --- |
| Every known NEW-build creator is routed | Complete source/call-flow inventory plus entry-point/race tests. Does not prove absence of OLD contexts. |
| No OLD live context in this Storage/lock scope can write the mirror | A justified lifecycle/admission policy with evidence outside current bytes or prior cooperation. New routing, a valid mirror or marker cannot establish it. |
| A bootstrap caller is the only accepted creator in its critical section | Routed creators plus exclusive named lock and current admission. A lock excludes cooperating callers, not uncooperative raw writers. Other accepted callers may exist and wait. |
| Deployment/build information exists | Identifies an artifact or this realm, not all resident realms. |
| Browser/context restart evidence exists | Must establish actual scope and compatible reload, including suspended/restored contexts. A foreground event or one-tab reload is insufficient. |

## 4. One NEW realm: feasible ordering, absent current boundary

There is **no single currently enforced earliest creator boundary**. [main.tsx](../src/main.tsx) mounts App; [AppContent](../src/components/AppContent.tsx):235-243 starts G5A control-plane discovery in a queued microtask independent of Health readiness. Startup's Health path uses [account single flight](../src/lib/healthBootstrapSingleFlight.ts), while [startupBootstrapCoordinator](../src/lib/startupBootstrapCoordinator.ts) starts independent domain entries and fences only their own UI generations. Neither establishes device admission. Readers invoke explicit opens/loads; routine session creation is lazy. No identity creator executes merely from module import. Other modules may hydrate unrelated settings/listeners on import; this is not a claim of a globally I/O-free application.

Thus new-realm routing is technically implementable before first identity creation. The authoritative owner must be a lazy domain-layer bootstrap/acquisition boundary below ALL entry points, not a view effect. AppContent can schedule/prewarm it and present readiness, but cannot be the sole gate or evidence owner. `productionSession` must wait before first IDB open; runtime controller before helper/discovery; reader opens/loads before identity-dependent IO. Post-await read guards must never manufacture identity. Each entry must enforce the ordering even when called outside AppContent (export/restore/tests), or remounted/retried under StrictMode.

Required dependency order, NOT an implementation in this PR:

1. Compatible build entry installs/owns the acquisition dependency without creator I/O.
2. Admission policy evaluates the relevant storage/context scope and justifies old-context lifecycle evidence; no guessed flag.
3. All accepted creation-capable acquisitions use that owner; exclusive authority lock serializes admitted create/adopt/recovery and re-reads persisted state.
4. Coherent READY/marker yields the exact device output; then account/generation-scoped repository, sync or control-plane acquisition may proceed under their unchanged contracts.
5. Slice 2 separately adds token capture, async-gap revalidation and source-owned final-use fencing; account/generation/coordinator fences remain independent.

There is no production identity worker/service worker to route in this tree. Existing `SyncWorkerLeaseRecord` means a leased application sync operation, not a registered browser Worker. A future worker/extra entry point must join the same inventory before admission is claimed.

## 6. Browser/storage scope and impossibility proof

The approved scope is participating contexts sharing the **same identity Storage AND authority-lock scope**, not every physical device/account worldwide. [Web Locks specification](https://w3c.github.io/web-locks/) scopes lock managers by storage bucket; [API documentation](https://developer.mozilla.org/en-US/docs/Web/API/Web_Locks_API) describes cooperating tab/worker locking. An uncooperative raw write is not blocked by a new lock. [Storage events](https://developer.mozilla.org/en-US/docs/Web/API/Window/storage_event) notify other sharing contexts, not the writing window; event absence cannot enumerate old realms. These browser facts support the following inference, not an executed QA result.

| Context | Admission requirement / limitation |
| --- | --- |
| Same JS realm | All known accepted creator entries behind one owner; no import-time creator. Deterministic routing/race tests can establish this for a reviewed build. |
| Another same-origin tab in same storage context | Must be compatible/cooperating or genuinely retired before admitted bootstrap/guarantee. This includes hidden/suspended/back-forward-restorable contexts, not only foreground tabs. |
| Installed Edge app window | If it shares the relevant identity Storage/lock scope, it belongs in the SAME admission set along with browser tabs. UI closing one window is not a demonstrated retirement of all contexts. [Microsoft's PWA overview](https://learn.microsoft.com/en-us/microsoft-edge/progressive-web-apps/) describes installed browser applications; exact Absinthe sharing/relaunch behavior needs physical QA. |
| iPhone Safari Home Screen context | Determine actual Storage/lock sharing with Safari/other installed copies through physical QA. Shared scope requires joint admission; separate partition is a distinct local authority. Do not infer either solely from same URL or icon. Suspend/app-switch dismissal/restart semantics must be tested. |
| Different browser/profile/origin/storage partition | Separate authority context; no cross-installation quiescence proof or device synchronization is required. Do not change origin/profile or clear storage as a migration workaround. |

**Technical impossibility under the stated observations:** world X has no old tab; world Y has an old suspended tab running the raw helper, with identical current localStorage bytes. The old tab has never registered or taken the new lock and emits no message while suspended. Every finite new-build byte read, heartbeat wait or new lock query can return identical observations in X and Y. On resume, Y may write the mirror. Therefore current bytes alone, without prior old-client cooperation or justified external lifecycle evidence, cannot prove absence of that capability. Longer timeout, valid UUID, missing marker, fresh authority, build hash and cryptographic hashing do not create the missing observation. This is not merely a missing implementation of a clever registry.

First rollout inherits this paradox: pre-authority clients registered neither old-build membership nor admission. A registry introduced now observes only joiners. A durable latch can store a policy decision/history after trusted admission but cannot retroactively establish first quiescence. The approved forward-only requirement is technically fixed; the relevant admission/evidence/support policy choices are product-owner approved in §10, while the operational procedure, implementation, and required supported-platform physical evidence remain NOT EXECUTED; unsupported-context handling remains governed by the approved bundle.

Clean-install result: all three identity values absent + compatible build + no residual old context **by justified construction** is safe for the approved creator bootstrap protocol. The application currently observes only the first two, not the third. A genuinely fresh isolated storage/container lifecycle could provide the construction premise; metadata absence, site-data clearing while tabs remain, or a new Home Screen icon cannot. This task authorizes no profile switch, origin change or deletion. Residual IDB is not presumed empty; ownership stays under original namespaces, with no reassignment/clear/rebind.

Existing-install result: exact valid legacy mirror with absent authority/marker is eligible bytes, NOT sufficient admission. Require new-build creator routing, evidence-backed retirement/compatibility of old same-scope contexts, verified loaded-build compatibility, and unchanged residual namespace/writer ownership. Preserve exact device/case. Retained marker + missing authority, malformed/future records or unexplained torn state retain the approved fail-closed rules; a new admission policy cannot repair those automatically.

## 8. Reader-only ceiling and writer firewall

A bounded admission model exists CONDITIONALLY in local authority metadata + domain startup lifecycle + compatible-context coordination/operational evidence. No technical necessity has been found to change mutation identity, outbox identity, request digest, delivery binding, CAS, transport, authorityEpoch, pending writer records or canonical writer enablement. None of A-F by itself supplies missing old-client evidence, and no runtime-ready model is selected yet.

Its ceiling: preserve exact established device output and existing creator/reader recovery roles; serialize identity acquisition BEFORE creating a new repository/session; do not transfer residual namespaces; admission/lifetime metadata never enters wire/persistence identities; existing pending payload/hash/binding/receipt bytes remain unchanged. Identity-acquisition routing is part of the prerequisite proof, while reader token/final-publication adoption remains Slice 2. The future plan must allocate thin acquisition routing of every creation-capable site explicitly; leaving a guard able to create later defeats initial startup admission. It must not require completed Slice 2 final-publication adoption to justify its own bootstrap, which would be circular.

Healthy-path role/output-preserving acquisition ordering is not permission to alter sync behavior. If implementing C/F denial would pause an already active cached Health writer, evict `productionSessions`, rebind delivery, change existing Health bootstrap readiness/retry, broaden recovery/reset, or otherwise change established sync/control-plane semantics, classify that part `CROSSES_WRITER_BOUNDARY` and STOP for a separate high-risk task. PD approval alone cannot waive this firewall. Explicitly review startup availability effects before claiming the reader-only ceiling is achieved. No writer shutdown/retirement is implemented here, and a browser restart procedure must account for in-flight unsaved work without silently cancelling or discarding it.

For EACH model: A/B/C/D/F can be metadata/lifecycle-only subject to that ceiling; E cannot retrofit old realms and its data-plane adaptations cross the firewall. ALL models cross it if they change any listed frozen field, cached writer ownership/recovery/transport semantics or canonical activation. The authority lock is not a worker lease or server lock; do not nest it with network/domain scans or wait for user action while held. No DB v7/schema v1/store/index/keyPath/WorkoutSessionV1/backend change is needed or authorized by this characterization.
